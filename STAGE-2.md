Дата: 17.10.2026. Переход разрешён прямым поручением владельца. Код готов к настройке и локальной проверке с настоящим ботом. **Этап не принят.** Деплой, домен и Mini App не выполнялись.

## Архитектура

Один процесс Node.js >=22.18 обслуживает HTTP на loopback, SQLite и Telegram long polling. Внешние npm-зависимости не нужны. Сайт получает личный журнал только после входа. Демо остаётся локальным и не отправляется в API. База создаётся в `data/rhythm.sqlite`; новый журнал пустой. Запуск и перенос старой истории описаны в README.

| Таблица | Данные |
| --- | --- |
| `entries` | Каждое занятие отдельной строкой, даты создания и изменения |
| `journal` | Версия, настройки, категории, проекты, снимки расписания и паузы |
| `account`, `sessions` | scrypt-хеш пароля, хеши сеансов, CSRF-токены, срок действия |
| `telegram`, `links` | Проверенная привязка владельца, хеш одноразового кода на 10 минут |
| `prompts` | Интервал, часовой пояс, Telegram message ID, отправка/ответ/ошибка, попытки и задержка |
| `updates`, `meta` | Идемпотентная обработка Telegram update и позиция long polling |
| `pending` | Короткий текст, ожидающий выбора интервала или подтверждения замены, на 10 минут |
| `requests` | Идентификаторы и хеши сохранений API; срок хранения 7 дней |

`entries` не содержит демопример. Часовой контекст записи берётся из снимка расписания её даты. Первая отправка опроса фиксирует расписание дня. Данные одного владельца; создание второго аккаунта не предусмотрено.

## Контракт API

Все пути `/api/`; нет CORS. Изменяющие запросы требуют cookie, точный Origin этого сайта и `X-CSRF-Token`. Формат тела — `application/json`. Лимит журнала 12 МБ, общий лимит запроса 12 МБ + 4 КБ.

| Метод и путь | Назначение |
| --- | --- |
| `GET /session` | Статус входа и CSRF для текущего сеанса; не возвращает записи |
| `POST /login` | `{password}`; HttpOnly/SameSite=Strict cookie на 12 часов |
| `POST /logout` | Удаляет сеанс |
| `GET /journal` | `{revision, workspace}` личного журнала |
| `PUT /journal` | `{revision, workspace, requestId, clear?}`; атомарная замена с валидацией |
| `GET /telegram` | Статус настройки/привязки, последняя доставка и ошибка; без токена и chat ID |
| `POST /telegram/link` | Одноразовая ссылка привязки |
| `DELETE /telegram` | Отключение привязки, удаление ожидающих вопросов и ответов; занятия сохраняются |

Устаревшая версия возвращает 409. Повтор того же requestId с тем же телом возвращает актуальное состояние без повторного изменения. Изменённое тело с использованным requestId отклоняется. Сайт сохраняет неуспешное изменение в памяти и предлагает повтор, экспорт JSON или загрузку свежей базы с подтверждением. При неудаче не показывает сохранение в базе как успешное. Перезагрузка с несохранёнными изменениями вызывает предупреждение браузера.

## Правила Telegram

- Принимаются только личные сообщения от привязанного Telegram user/chat. Группы игнорируются. Смена аккаунта требует отключения на сайте и новой ссылки.
- Опрашивается завершённый интервал независимо от записей с сайта или Telegram, включая разделённые записи. Паузы исключаются. Ручной ввод до конца интервала не считается доставкой вопроса; планировщик всё равно отправляет его один раз. Планировщик проверяет время каждые 15 секунд. Окно актуальности — текущая и следующая минута после конца интервала; устаревшие вопросы не догоняются пачкой. Ранее отправленные, ошибочные и неопределённые доставки не сбрасываются из-за записей.
- Дни, часовой пояс, конец дня, паузы, короткий последний интервал, 24:00 и повторный час при смене сезонного времени учтены. Ночные окна через полночь не поддерживаются настройками.
- Ответ на конкретное сообщение-вопрос относится к его исходному интервалу, включая поздний ответ. Обычный текст описывает **текущее занятие**: берётся время отправки сообщения в Telegram, сетка от полуночи с настроенным шагом. 02:20 при шаге 30 минут → 02:00–02:30, 02:30 → 02:30–03:00. Завершения интервала ждать не нужно.
- Повторный обычный текст добавляет занятие внутрь одной Telegram-записи блока, сохраняя предыдущие тексты, их ID, время отправки, категорию и проект интервала. Длительность не умножается. Старые вопросы и пропуски не влияют на выбор блока. Вне часов опроса ручной ввод разрешён. Запись с сайта автоматически дополняется с сохранением исходного текста; разделённые интервалы редактируются на сайте.
- Повторный ответ на заполненный Telegram-интервал добавляет занятие, не заменяя предыдущие. Добавление к записи с сайта не требует подтверждения и сохраняет прежний текст, категорию и проект. Разделённый или частично перекрытый интервал меняется на сайте. Кнопка продолжения копирует текст предыдущей записи только в указанный интервал; категория/проект остаются настраиваемыми на сайте.
- `/pause` — на час или до конца окна; `/resume` — закончить активную паузу; `/end` — пауза до конца дня; `/site` — локальный адрес с выбранным портом; `/help` — справка.
- Голосовые файлы не распознаются; бот предлагает текст или системную диктовку, сохраняя ожидаемый интервал.
- Обработка update и изменение журнала — одна SQLite-транзакция. Подтверждение Telegram отправляется после commit. Если подтверждение не дошло, запись может быть уже сохранена — это отражается в статусе.
- Отправка напоминания и ответ — разные состояния. HTTP 429 повторяется до 3 попыток с учётом retry_after и актуальности интервала; задержка хранится в БД. При сетевой неопределённости не выполняется автоматический повтор. Незавершённая отправка после перезапуска помечается как неопределённая. Гарантии exactly-once внешней доставки Telegram нет.
- При настроенном webhook бот останавливает инициализацию с сообщением, не удаляя существующий webhook самостоятельно. Для разработки нужен отдельный бот без webhook. Запускайте один экземпляр сервера на одну базу и токен.

## Осталось до приёмки

1. Владелец запускает `npm run setup`, сохраняет показанный пароль и выполняет `npm start`.
2. Добавляет токен своего нового бота в `.env` локально, перезапускает сервер, привязывает Telegram через сайт.
3. Сохраняет подходящее расписание. Проверяет настоящий вопрос, ответ, появление записи на сайте, повтор/поздний ответ и паузу. Проверяет работу при закрытой вкладке.
4. При необходимости явно переносит прежнюю локальную историю через JSON или «Перенести из браузера» на том же origin.
5. Принимает этап 2 или сообщает замечания. До этого этап 3 не начинается.

## Границы защиты

Сервер не выставлен в интернет: loopback HTTP, строгий Host, отсутствие CORS, CSRF, лимиты, SQL-параметры и разрешённый список статических файлов. `.env` и SQLite не отдаются через HTTP и не включаются в Git. Runtime-файлы создаются с umask 077; основная база — 0600. Пароль сбрасывается только локальной CLI-командой, история сохраняется.

SQLite, WAL, скачанные JSON/CSV и старый localStorage не зашифрованы приложением. Удаление — логическое; ранее скачанные файлы, внешние резервные копии, остатки на носителе и история переписки Telegram автоматически не очищаются. Это не аудит защиты macOS или аккаунта Telegram. Удалённые подтверждения в Telegram также не означают удаление сообщения из его инфраструктуры.

Перед публичной эксплуатацией обязательны HTTPS, Secure-cookie, доверенный домен, постоянный процесс, защищённые секреты, backup/restore и повторная проверка безопасности. Эти работы относятся к этапу 3 и пока не выполнялись. Настоящий Telegram-токен, внешняя доставка, реальный iPhone и продакшен-нагрузка в этой проверке не использовались.
