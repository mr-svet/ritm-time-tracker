# Ritm — 了解你的时间都去哪了

[![Ritm 实际界面，点击打开访客演示](assets/github-preview.png)](https://ritmday.space/)

## 在线体验 Ritm

[在浏览器中打开 Ritm](https://ritmday.space/)，无需安装即可了解应用的界面和功能。在登录页面选择**访客（Visitor）**模式，通过示例数据了解时间日记、图表和设置。访客模式无需密码。

Ritm 是一款可自行部署的时间日记应用，由网站、SQLite 数据库和可选的 Telegram 机器人组成。每隔 30 分钟，用几句话记录正在做的事，帮助你了解一天的时间花在哪里，而不是把每一刻都变成效率竞赛。

你可以在网站上记录，也可以直接回复 Telegram 机器人。记录会汇成每日时间线、时间分布图，以及按天或按月查看的趋势。无需 ChatGPT 账号、AI API 或语言模型订阅。

**每个部署实例都使用自己的数据库。** 克隆本仓库不会让你的记录连接到作者的服务器。启用 Telegram 功能时，请使用你自己的机器人令牌。

## 功能

- 在网站或 Telegram 中记录活动，并按你选择的时段和日期，每隔 15、30 或 60 分钟提醒一次。
- 早晨可选择“刚刚醒来”或输入其他起床时间（HH:MM）；之后按起床时间安排活动提醒。点击“睡觉”可结束当天提醒。
- 在同一个时间段内保留多项活动。新消息会追加到已有记录，不会覆盖之前的内容，也不会重复计算时长。
- 编辑历史记录或单项活动、拆分时间段，以及稍后补填空白。
- 新建、重命名、设置颜色、归档或删除分类，并按项目整理活动。删除分类后，旧活动仍保留为未分类，机器人不再提供该分类。
- 自行选择哪些分类计入目标，查看每日或每月趋势。
- 搜索城市来选择时区。历史日期保留当时的时间安排和时区。
- 在英语、俄语界面，以及浅色、深色主题之间切换，适配电脑和手机。
- 无需密码即可打开独立访客演示，内含滚动十二个月的多样化示例记录、八个分类和三个项目。
- 导入或导出 JSON、按筛选条件导出 CSV，以及创建经过完整性校验的 SQLite 备份。

- 可按日、周或月查看统计；可关闭项目字段和图表，同时保留历史项目关联。机器人语言可通过“设置 → 语言”切换。

## 本地运行

需要 **Node.js 22.18 或更高版本**。运行应用无需安装第三方依赖。

```bash
git clone https://github.com/mr-svet/ritm.git
cd ritm
npm run setup
npm start
```

打开 **[http://127.0.0.1:4173/](http://127.0.0.1:4173/)**。

`setup` 会创建所有者账号，并且只显示一次随机密码。请将密码保存到密码管理器中。再次运行此命令不会更改已有密码。如需生成新的所有者密码、结束当前会话并保留日记记录，请运行 `npm run reset-password`。

使用日记时，请保持服务器运行。按 **Ctrl+C** 可停止服务器。如果端口 4173 已被占用，请停止占用该端口的进程，或改用其他端口：

```bash
PORT=4174 npm start
```

本地模式仅监听 `127.0.0.1`，因此只有运行应用的这台电脑可以访问。如需从其他设备使用，或在电脑关机后继续接收机器人提醒，请将应用部署到持续运行的服务器上。

## 连接你自己的 Telegram 机器人

1. 打开官方 [@BotFather](https://t.me/BotFather)，发送 `/newbot` 并按照提示操作。本地开发建议使用独立机器人，且不要为它配置 webhook。
2. 如果还没有 `.env` 文件，将 [`.env.example`](.env.example) 复制为 `.env`，然后在本地填入令牌：

   ```dotenv
   TELEGRAM_BOT_TOKEN=your_botfather_token
   ```

3. 重新运行 `npm start`。即使不填写机器人令牌，网站和数据库也可以使用。
4. 以所有者身份登录，打开 **Settings → Telegram → Connect Telegram**，在 Telegram 中打开一次性链接并点击 **Start**。链接有效期为 10 分钟。
5. 选择时区、记录时段和日期，然后保存。如果当天已经有记录或暂停时段，新安排将从次日生效。

令牌只保存在服务器端。不要将 `.env`、数据库或备份放进 Git、截图或聊天消息。同一个令牌只能运行**一个机器人进程**：在服务器上启用该令牌前，请停止本地实例。

### 提醒与记录的逻辑

定时提问针对刚刚结束的时间段，即使该时间段已有记录，机器人仍会提问。先选择分类；若选择“工作”且已开启项目功能，可直接点击项目名称，将其记录为活动，或点击“自己填写”输入描述。其他分类则直接输入简短描述。分类选择与该条提问绑定，有效期为 30 分钟。其他分类可以通过机器人的翻页按钮查看。

如果直接发送普通消息，而不是回复某条提问，消息会按照发送时间和日记时区对应到**当前时间段**。完成一次机器人提问后，再发送普通消息会先要求选择分类，然后才保存。例如间隔为 30 分钟时，12:20 发送的消息属于 12:00–12:30。继续记录会在同一时间段内追加活动，不会覆盖先前内容，也不会自动填入更早的空白。之后的定时提问也可以继续补充同一时间段的记录。

如果网站上已有同一时间段的记录，回复会追加到该记录中。项目保持不变；明确选择的分类适用于整个时间段。应用不会猜测每项活动的具体时长，同一时间段只计算一次。已拆分或部分重叠的时间段可以在网站上编辑。

继续活动按钮只会重复上一时间段中的最后一项活动，不会复制整个汇总。重复点击不会再次添加同一项延续活动。回复已经使用、过期或无法识别的分类请求时，机器人会提示未保存，而不会悄悄记入当前时间段。重新选择分类会替换之前尚未完成的选择，不会复制先前的活动。

| 命令 | 操作 |
| --- | --- |
| `/help` | 查看帮助 |
| `/settings` | 打开机器人设置并切换语言 |
| `/sleep` | 记录就寝时间，停止当天提问 |
| `/pause` | 暂停提醒一小时 |
| `/resume` | 恢复提醒 |
| `/end` | 暂停当天剩余时间的记录提醒 |
| `/site` | 打开网站 |

可以使用键盘的语音输入功能，将语音转成普通文字后发送。应用不会转写语音消息。在 Telegram 发送 `/language` 可独立切换机器人的俄语和英语。

当你没有编辑表单时，网站每五秒检查一次更新。机器人会遵守暂停设置和休息日，漏记时段会保持空白。停机后恢复运行时，不会集中发送积压的旧问题。提问的发送状态和回复的保存状态会分别显示在设置中。

## 日记与趋势

快速记录会自动使用所选时区的当前时间段。时间段更新时，不会清空已输入的草稿；也可以手动调整时间。历史记录保留原有日期和时间。当前时间段尚未结束时也可以保存，但不能填写完全位于未来的时间段。

打开 **Journal → All entries** 查看历史。点击编辑按钮修改记录，或展开活动列表编辑单条消息。分类和项目适用于整个时间段。

导航栏的第二项「总览」按分类和日期显示累计时长。默认范围从上个月同日到今天；横向滚动可查看更早日期，最新日期固定在分类旁。点击时长可查看对应时间段和活动；点击起床或就寝时间可更正实际时间。底部显示每日总计，同一时间段的多条消息不会重复计算。分类排序在网站和机器人之间共用。此页不再显示生产率评分和公式。

网站默认使用俄语，可切换为英语。语言、主题和日景偏好通过 `ritm-ui-v2` 保存在当前设备上，与日记数据分开。切换语言不会翻译或改写你的个人记录和分类名称。日期、时长、城市名称及 CSV 列标题会随界面语言切换。**本文件是中文使用说明；网站界面目前支持英语和俄语。**

**Check connection** 用于检查网站服务器是否可连接，并显示成功或错误提示。它不会检查 Telegram 连接，也不会启动服务器。

## 访客演示

登录页选择 **Visitor → Open demo** 即可进入，无需密码。私人日记仍需所有者密码。

访客会获得一份全新的虚构日记，可以体验记录、分类、项目、时间安排和图表。修改只保留在当前标签页的内存中，刷新后即会重置。访客日记不会从浏览器存储中读取，也不会写入浏览器存储或所有者的数据库。设备上的语言、主题和日景偏好另行保存。

访客无法访问私人日记 API、导入导出功能或实际 Telegram 机器人。这些限制由服务器执行，而不仅仅是隐藏界面按钮。访客会话最长持续两小时。所有者会话最长持续 12 小时。

同一个浏览器配置文件只能保持一种当前角色。如需同时测试所有者和访客模式，请使用不同的浏览器配置文件。

## 数据与备份

数据库默认位于 **`data/rhythm.sqlite`**，可通过 `DATA_DIR` 更改目录。`entries` 表保存时间段记录；`entries.activities` 字段以 JSON 格式保存各项活动，包括标识符、文本，以及已知的消息 UTC 时间戳。后端详情见俄语文档 [STAGE-2.md](STAGE-2.md)。

```bash
npm run db:entries
npm run db:backup
```

第一条命令只读显示最近的记录。第二条命令会在应用运行期间创建 SQLite 快照并校验完整性，包括已经提交的 WAL 数据。默认保存到 `backups/`，也可以通过 `BACKUP_DIR` 指定目录。请另外保留一份服务器以外的备份。

不要只复制正在运行的数据库的 `.sqlite` 文件。如果需要手动复制文件，请先停止应用，再复制整个 `data/` 目录，包括可能保留的 WAL 文件。

JSON 导出会保留单项活动，并支持导入旧版 version-1 日记。CSV 每个时间段占一行，避免重复计算时长。导出文件和 SQLite 数据库**未加密**。

旧版仅保存在浏览器中的个人日记不会自动迁移。可以在相同地址和端口上使用 **Settings → Move from browser**，或从旧版导出 JSON 后导入服务器日记。替换数据前请先下载备份。被旧版本覆盖的历史消息无法自动恢复。

## 仅前端预览

```bash
npm run dev
```

此命令运行静态前端，使用浏览器存储键 `ritm-local-v1`，不连接数据库 API 或实际机器人。`ritm-preview.html` 是该模式的独立 HTML 版本，可运行 `npm run build` 重新生成。它与后端提供的独立访客演示是两种不同模式。

## 服务器部署

仓库中的 [Dockerfile](Dockerfile) 和 [compose.yaml](compose.yaml) 面向 **Dokploy 的 Docker Compose 部署**。Compose 文件依赖已存在的 `dokploy-network`，不能直接作为独立公共服务器的完整配置使用。

请使用自己的 HTTPS 域名，并将 `APP_ORIGIN` 设置为网站的准确来源地址。在服务器环境变量中配置自己的机器人令牌。为 SQLite 和备份保留持久化数据卷，并只运行一个应用实例。HTTPS 由反向代理处理，不要直接公开应用的内部端口。

密码以带盐的 scrypt 哈希保存。生产环境使用 Secure、HttpOnly、SameSite Cookie，并检查请求来源和 CSRF。也需要保护服务器、磁盘和备份；密码登录并不会对日记文件本身进行加密。

版本发布状态和待完成的验证见俄语文档 [DEPLOYMENT.md](DEPLOYMENT.md)。应用面向一个所有者及访客演示，不提供公开注册或多个独立用户账号。Telegram Mini App 尚未实现。


测试使用临时数据库和模拟 Telegram 通信，不会发送真实消息或修改个人日记。修改前端模块或样式后，请重新生成独立 HTML。

产品范围见俄语文档 [PRD.md](PRD.md)。自动化测试不能代替使用你自己的实际机器人检查消息送达和回复保存。

## 总览与语言

总览的单元格显示各分类每日累计时长，点击后可查看具体活动并前往日记。表格无需横向滚动，可用按钮切换日期。分类可拖动排序，顺序同步用于 Telegram 机器人。
